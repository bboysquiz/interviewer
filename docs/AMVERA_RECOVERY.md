## 1. Создать приложение в доступном регионе

Создай новый сервис типа «Приложение», например `interviewer-restored`,
в доступном регионе Amvera. Старый проект сохрани: поддержка ещё может
восстановить более свежие данные и его настройки.

Используй одну реплику приложения. Отдельный PostgreSQL для этого проекта
не нужен: SQLite и изображения хранятся в `/data`.

Если нужны штатные бэкапы постоянного хранилища Amvera, по текущей
[документации](https://docs.amvera.ru/applications/backups.html) они доступны
на тарифе «Начальный Плюс» и выше. Актуальную стоимость проверь в кабинете.

## 2. Загрузить код

Во вкладке «Репозиторий» нового сервиса скопируй его Git URL. Используй
именно этот адрес, включая новый регион, а не старый `git.msk0.amvera.ru`.

Из PowerShell в `S:\ProgrammingInterviewer`:

```powershell
git remote add amvera-recovery "GIT_URL_НОВОГО_СЕРВИСА"
git push amvera-recovery HEAD:master
```

Вместо заполнителя подставь URL из кабинета. Для авторизации нужны данные
аккаунта Amvera. Это отдельная учётная запись от пользователя приложения
`bboysquiz`. Если remote `amvera-recovery` уже существует, обнови его командой
`git remote set-url amvera-recovery "GIT_URL_НОВОГО_СЕРВИСА"`.

В репозитории уже есть `Dockerfile` и `amvera.yaml`:

```yaml
meta:
  environment: docker
  toolchain:
    name: docker
build:
  dockerfile: Dockerfile
run:
  command: node
  args: server/dist/index.js
  persistenceMount: /data
  containerPort: 3000
```

Не загружай локальные `.env` в Code. Не меняй `DATABASE_PATH` на путь
внутри `/app`: данные должны находиться в постоянном хранилище.

## 3. Настроить домен, переменные и секреты

Включи бесплатный домен нового сервиса в его настройках. Старый домен
может остаться привязан к старому проекту; его перенос уточни у поддержки.

Во вкладке «Переменные» добавь:

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=3000
DATABASE_PATH=/data/app.db
UPLOADS_DIR=/data/uploads
CLIENT_ORIGIN=https://НОВЫЙ-ДОМЕН.amvera.io
AI_PRIMARY_PROVIDER=gemini
AI_FALLBACK_PROVIDER=groq
GEMINI_DOH_URL=https://dns.comss.one/dns-query
GEMINI_VISION_MODEL=gemini-2.5-flash
GEMINI_INTERVIEW_QUESTION_MODEL=gemini-3.1-flash-lite-preview
GEMINI_INTERVIEW_EVALUATION_MODEL=gemini-3.1-flash-lite-preview
GROQ_VISION_MODEL=qwen/qwen3.8-27b
GROQ_INTERVIEW_QUESTION_MODEL=qwen/qwen3.8-27b
GROQ_INTERVIEW_EVALUATION_MODEL=qwen/qwen3.8-27b
AI_INTERVIEW_CONTEXT_MAX_CHARS=12000
```

Замени `CLIENT_ORIGIN` на фактический HTTPS-адрес без завершающего `/`.
Секретами добавь `GEMINI_API_KEY` и `GROQ_API_KEY`. Их значения сохранились
в локальном `server/.env`; в архив кода и подготовленный пакет они не включены.
Не копируй файл `.env` целиком: в нём есть локальные пути.

`VITE_API_BASE_URL` для этого деплоя не задавай: UI и API обслуживает один сервер.
Старые Groq-модели из прежних переменных замени указанными выше. Актуальный
список доступен в [документации Groq](https://console.groq.com/docs/models).
Доступность AI также зависит от действительности ключей и квот аккаунтов.

После изменения переменных перезапусти контейнеры, иначе настройки не
применятся. [Документация переменных Amvera](https://docs.amvera.ru/applications/configuration/variables.html).

## 4. Перенести базу и изображения

Дождись первого успешного запуска: по документации Amvera постоянное
хранилище Data появляется после первого развёртывания.

Останови новый сервис или выставь количество реплик в 0 и дождись остановки.
Замена файлов SQLite должна происходить, когда приложение не использует базу.

Во вкладке «Репозиторий» выбери **Data**, затем «Загрузить данные».
Загрузи содержимое подготовленной папки `data` с сохранением папки `uploads`.
Итоговая структура в Data должна выглядеть так:

```text
app.db
uploads/
  0047e166-d131-419a-b6c3-cbf51e8763bc.png
  ...остальные изображения...
```

Если первый запуск создал пустую базу, перед загрузкой восстановленной
убери из Data её `app.db`, `app.db-wal` и `app.db-shm`. Это касается только
нового пустого сервиса: существующие данные сначала скачай отдельно.
Старый WAL нельзя оставлять рядом с заменённым `app.db`.

Не загружай внешнюю папку `data` или `interviewer-data` как дополнительный
уровень: сервер должен увидеть `/data/app.db` и `/data/uploads`, а не
`/data/data/app.db` или `/data/interviewer-data/app.db`.

Если загрузчик не переносит папки, можно загрузить готовый архив
`interviewer-data-ready.tar.gz` в Data и передать поддержке эту инструкцию:
«При остановленном сервисе распаковать архив в постоянное хранилище `/data`,
чтобы в его корне появились `app.db` и `uploads`, предварительно сохранив
созданную первым запуском базу и её WAL/SHM». Само наличие `.tar.gz` в Data
ещё не означает восстановление: должны появиться распакованные файлы.

Работа с Data описана в
[документации хранилища Amvera](https://docs.amvera.ru/applications/storage.html).

## 5. Запустить и проверить

Верни одну реплику и запусти сервис. В логах должны быть:

```text
SQLite database path: /data/app.db
Uploads directory: /data/uploads
```

Открой `https://НОВЫЙ-ДОМЕН.amvera.io/api/health`: ожидается `ok: true`.
Войди пользователем `bboysquiz` с прежним паролем. Новая регистрация не нужна.

Проверь категории, несколько заметок, изображения и историю собеседований.
В снимке 31 категория, 30 заметок и 1588 вложений; 1244 изображения имеют
статус готового AI-анализа. Статусы ожидания и ошибок анализа также перенесены.

Перезапусти сервис ещё раз и убедись, что данные сохранились. AI проверь
отдельно после переноса ключей: локальная проверка восстановления не
отправляла платные запросы провайдерам.

## 6. Перенаправить GitHub Actions

В GitHub открой репозиторий → Settings → Secrets and variables → Actions.
Обнови secrets:

- `AMVERA_GIT_URL`: Git URL именно нового сервиса и региона.
- `AMVERA_GIT_USERNAME`: логин аккаунта Amvera.
- `AMVERA_GIT_PASSWORD`: пароль аккаунта Amvera.

Сделай это до следующего push в GitHub, иначе workflow отправит код в старый
регион. После настройки будущие коммиты отправляй `git push origin main`.

Текущий workflow публикует код в Amvera только при push в `main`.
Ручной `Run workflow` запускает сборку, но не job `sync-amvera`. Первый
деплой из шага 2 выполняется прямым push и не зависит от этого ограничения.

Зелёный GitHub Actions означает успешную проверку и отправку кода, а статус
сборки и запуска нового приложения нужно смотреть отдельно в Amvera.

## 7. Держать отдельную резервную копию

Сохрани исходные архивы и подготовленный пакет за пределами Amvera.
Для следующих копий есть `npm run backup:data`: он копирует базу и изображения.
Архив из `/data/backups` нужно также скачивать на компьютер или в другое
хранилище. Копия на том же серверном диске не заменяет независимый бэкап.
